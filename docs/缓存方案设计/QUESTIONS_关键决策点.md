## Q1: 缓存基础设施选择 🔥

**问题**: 选择什么缓存技术栈？

**选项**:
1. **应用级内存缓存** (推荐)
   - 使用 `sync.Map` 或第三方库如 `go-cache`
   - 优点: 简单、快速、无外部依赖
   - 缺点: 单实例、重启丢失
   - 适合: 当前单实例部署场景

2. **Redis缓存**
   - 引入Redis作为缓存层
   - 优点: 分布式、持久化、功能丰富
   - 缺点: 运维复杂度、网络开销
   - 适合: 分布式部署场景

## Q2: 缓存实现策略 📊

**问题**: 采用什么缓存更新策略？

**选项**:
1. **Cache-Aside模式** (推荐)
   - 应用负责缓存维护
   - 更新时先更新DB，再删除缓存
   - 查询时缓存未命中则查DB并写入缓存

2. **Write-Through模式**
   - 同时更新缓存和数据库
   - 强一致性但性能稍差
