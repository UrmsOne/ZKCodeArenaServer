# CONSENSUS - 每日一题与题目统计功能共识

## 需求描述和验收标准

### 功能1: 每日一题功能
**业务需求**: 为用户提供每日统一推荐题目，提升用户学习积极性
**技术方案**: 
- **推荐策略**: 全局统一，所有用户当天看到相同题目
- **缓存策略**: 每天生成并缓存当日推荐
- **推荐算法**: 随机推荐策略（从已发布的公开题目中随机选择）

**验收标准**:
- [ ] 提供`/api/daily-problem`接口，返回当日推荐题目
- [ ] 同一天所有用户获取相同推荐
- [ ] 每天零点自动更新推荐（或首次访问时更新）
- [ ] 支持题目详情、用户状态等完整信息
- [ ] API响应时间 < 100ms

### 功能2: 轻量级题目难度统计API
**业务需求**: 为前端提供题库概况，显示各难度题目数量
**技术方案**: 独立轻量级API，避免获取过多统计数据

**验收标准**:
- [ ] 提供`/api/problems/difficulty-stats`接口
- [ ] 返回格式：`{"easy": count, "medium": count, "hard": count}`
- [ ] API响应时间 < 50ms
- [ ] 支持缓存优化

### 功能3: 数据库更新逻辑优化
**业务需求**: 解决空值更新问题，提升代码质量和可维护性
**技术方案**: 
- **更新策略**: 采用"omitempty + BSON Marshal + Unmarshal 构造 $set"
- **解耦策略**: 通用函数解耦MongoDB逻辑
- **改造范围**: Problem、Submit、TestCase三个核心模块

**验收标准**:
- [ ] 实现通用的`BuildUpdateDocument`函数
- [ ] 重构Problem、Submit、TestCase的更新逻辑
- [ ] 解决空值覆盖问题（空字符串、零值等）
- [ ] 保持API接口不变，向后兼容
- [ ] 代码重复率降低，可维护性提升

### 功能4: 接口返回参数分析
**业务需求**: 提供详细的接口说明文档
**验收标准**:
- [ ] GetProblems接口完整参数说明
- [ ] SearchProblems接口完整参数说明  
- [ ] 包含字段类型、含义、使用场景
- [ ] 提供使用示例和最佳实践

## 技术实现方案

### 架构设计原则
1. **保持现有架构**: 遵循Server→Service→Database分层
2. **向后兼容**: 不影响现有功能和接口
3. **性能优先**: 优化数据库查询和缓存策略
4. **代码解耦**: 提取通用函数，减少重复代码

### 核心技术选型
1. **缓存方案**: 内存缓存存储每日推荐（24小时TTL）
2. **更新策略**: BSON反射机制构建$set文档
3. **随机算法**: 基于时间种子的伪随机选择
4. **数据库优化**: 复用现有索引，避免新增查询开销

### 集成约束
- 使用现有认证和权限体系
- 复用现有错误处理和日志体系
- 保持现有数据模型不变
- 遵循现有API设计规范
