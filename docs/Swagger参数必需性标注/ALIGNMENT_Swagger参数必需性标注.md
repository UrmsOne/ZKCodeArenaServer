#### 3.3 body参数（请求体参数）
❌ **状态**: 需要改进

**问题1**: 使用inline object定义
```go

// @Param request body object{real_name=string,email=string,bio=string,school=string,major=string,grade=string,class=string,phone=string} true "更新信息"
```

**问题2**: 请求结构体缺少binding标签
- 已经定义的结构体（如`models.UpdateProfileRequest`）存在
- 但Swagger注解中使用了inline object，没有引用结构体

## 🤔 需求理解

### 核心问题
前端开发者在使用Swagger文档时，无法直观地看到：
1. 哪些请求参数是必填的
2. 哪些请求参数是可选的
3. 请求体（JSON Body）中的字段哪些是必需的

### 期望结果
1. Swagger UI中能够清楚地看到每个参数的必需性标识
2. 必需参数应该有明确的标记（通常是红色星号*）
3. 可选参数应该能被识别出来

### 影响范围
- 前端开发人员使用API的便利性
- API文档的完整性和准确性
- 减少前后端联调时的沟通成本

## ❓ 疑问澄清

### 自动决策的问题

基于项目分析和行业最佳实践，以下问题我已自动决策：

#### Q1: 是否需要为所有可选字段添加binding标签？
**决策**: 否
- Go的binding标签只用于必需字段
- 可选字段通过以下方式标识：
  - 使用指针类型 + `omitempty`
  - 不添加binding标签
  - Swagger会自动识别

#### Q2: inline object是否都需要改为结构体引用？
**决策**: 是
- `UpdateProfileRequest`已经存在，但注解中使用了inline object
- 应该使用结构体引用，这样Swagger能自动识别字段的必需性
- 更改前：
```go
// @Param request body object{real_name=string,email=string...} true "更新信息"
```
- 更改后：
```go
// @Param request body models.UpdateProfileRequest true "更新信息"
```

#### Q3: query参数的default值是否需要标注？
**决策**: 需要
- 有default值的参数应该是可选的（false）
- 应该在描述中包含default值
- 示例：
```go
// @Param page query int false "页码" default(1)
```

#### Q4: formData类型的参数如何处理？
**决策**: 保持现有方式
- 文件上传使用 `formData file true`
- 已经符合规范，无需修改

### 决策点2: 是否需要添加示例值（example）？
**建议**: 可选，但推荐添加
- Swagger支持example标签，可以让文档更友好
- 示例：
```go
type LoginRequest struct {
    StudentID string `json:"student_id" binding:"required" example:"202101001"`
    Password  string `json:"password" binding:"required" example:"password123"`
}
```

**选项**:
- A. 为所有字段添加example（工作量大）
- B. 只为关键接口添加example
- C. 本次不添加example

**建议**: 可选
- binding标签支持更多验证规则，如email、url等
- 示例：`binding:"required,email"`

**选项**:
- A. 添加详细的格式验证
