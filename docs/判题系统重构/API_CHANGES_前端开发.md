## 📋 变更概述

本次判题系统重构主要涉及**数据模型增强**和**判题流程优化**，对前端 API 的影响主要体现在：

1. **测试用例模型增强**：支持测试用例级别的超时配置
2. **判题结果模型增强**：区分示例用例和隐藏用例的返回详细度
3. **判题流程异步化**：提交后立即返回，通过轮询或 WebSocket 获取结果

## 🔄 数据模型变更

### 1. TestCase（测试用例）模型变更

#### 新增字段

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `time_limit` | `int` | 否 | 测试用例级别的时间限制（毫秒），优先级高于题目默认值 |
| `memory_limit` | `int` | 否 | 测试用例级别的内存限制（MB），优先级高于题目默认值 |
| `score` | `int` | 否 | 用例分数（用于部分分支持，暂未启用） |

#### 示例 JSON

```json
{
  "id": "507f1f77bcf86cd799439011",
  "problem_id": "507f1f77bcf86cd799439012",
  "input": "1 2\n",
  "output": "3\n",
  "is_sample": true,
  "time_limit": 2000,      // 新增：可选，单位 ms
  "memory_limit": 512,     // 新增：可选，单位 MB
  "score": 10,             // 新增：可选，用于部分分
  "created_at": "2025-10-05T10:00:00Z"
}
```

#### 前端影响

- **题目管理页面**：需要支持为每个测试用例单独配置 `time_limit` 和 `memory_limit`
- **表单验证**：这两个字段为可选，如果不填则使用题目默认配置
- **UI 建议**：可以添加"使用题目默认值"的复选框，勾选后隐藏输入框

### 2. TestResult（测试用例结果）模型变更

#### 新增字段

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `is_sample` | `bool` | 是 | 标识是否为示例用例 |
| `expected` | `string` | 否 | 期望输出（**仅示例用例返回**） |

#### 字段行为变更

| 字段名 | 旧行为 | 新行为 |
|--------|--------|--------|
| `output` | 总是返回 | **仅示例用例返回**（隐藏用例不返回） |
| `error` | 总是返回 | **仅示例用例返回**（隐藏用例不返回） |

#### 示例 JSON

**示例用例结果**（返回详细信息）：
```json
{
  "test_case_id": "507f1f77bcf86cd799439011",
  "status": "wrong_answer",
  "time_used": 150,        // ms
  "memory_used": 2048,     // KB
  "is_sample": true,       // 新增
  "output": "4\n",         // 实际输出（示例用例返回）
  "expected": "3\n",       // 期望输出（新增，示例用例返回）
  "error": ""              // 错误信息（示例用例返回）
}
```

**隐藏用例结果**（不返回详细信息）：
```json
{
  "test_case_id": "507f1f77bcf86cd799439013",
  "status": "accepted",
  "time_used": 120,        // ms
  "memory_used": 1536,     // KB
  "is_sample": false       // 新增
  // 注意：output, expected, error 字段不返回
}
```

#### 前端影响

- **判题结果展示**：
  - 示例用例：显示实际输出、期望输出、错误信息（对比展示）
  - 隐藏用例：仅显示状态（AC/WA/TLE/MLE/RE）和资源使用情况
- **UI 建议**：
  - 示例用例可以展开查看详细对比
  - 隐藏用例只显示状态图标和统计信息

### 3. JudgeResult（判题结果）模型变更

#### 字段单位说明

| 字段名 | 单位 | 说明 |
|--------|------|------|
| `time_used` | 毫秒（ms） | 所有测试用例中的最大时间 |
| `memory_used` | KB | 所有测试用例中的最大内存 |

#### TestResult 中的单位

| 字段名 | 单位 | 说明 |
|--------|------|------|
| `time_used` | 毫秒（ms） | 单个测试用例的运行时间 |
| `memory_used` | KB | 单个测试用例的内存使用 |

#### 示例 JSON

```json
{
  "status": "wrong_answer",
  "time_used": 150,              // ms（最大值）
  "memory_used": 2048,           // KB（最大值）
  "compile_error": "",
  "runtime_error": "",
  "test_results": [
    {
      "test_case_id": "...",
      "status": "accepted",
      "time_used": 120,          // ms
      "memory_used": 1536,       // KB
      "is_sample": true,
      "output": "3\n",
      "expected": "3\n",
      "error": ""
    },
    {
      "test_case_id": "...",
      "status": "wrong_answer",
      "time_used": 150,          // ms
      "memory_used": 2048,       // KB
      "is_sample": false
      // 隐藏用例不返回 output, expected, error
    }
  ]
}
```

## 🔌 API 接口变更

### 1. 提交代码接口（无变更）

**接口**: `POST /api/submit`

**请求体**（无变更）：
```json
{
  "problem_id": "507f1f77bcf86cd799439012",
  "code": "public class Main { ... }",
  "language": "java"
}
```

**响应体**（无变更）：
```json
{
  "code": 200,
  "message": "提交成功",
  "data": {
    "id": "507f1f77bcf86cd799439020",
    "status": "pending"
  }
}
```

---

## ⚠️ 注意事项

1. **向后兼容性**：
   - 旧的测试用例数据（没有 `time_limit`, `memory_limit`, `score`）仍然有效
   - 前端需要处理这些字段为 `null` 或不存在的情况

2. **数据验证**：
   - `time_limit` 和 `memory_limit` 如果填写，必须 > 0
   - `score` 可以为 0（表示不计分）

3. **性能优化**：
   - 判题结果可能包含大量测试用例，建议使用虚拟滚动
   - 隐藏用例不返回详细信息，减少数据传输量

4. **用户体验**：
   - 示例用例失败时，显示详细对比帮助用户调试
   - 隐藏用例失败时，提示"请检查边界条件和特殊情况"
