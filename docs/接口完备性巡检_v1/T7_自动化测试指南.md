# T7：自动化测试基线指南

## 概述
本项目采用 Go 标准库 `testing` + `httptest` 进行 REST API 集成测试，确保整条链路（HTTP Handler → Service → Database）的正确性。

### 测试工具包 (`testutils`)

#### 核心函数

**1. SetupTestServer(t *testing.T) (*server.Server, func())**
- 创建测试服务器实例
- 初始化数据库和中间件
- 返回服务器实例和清理函数

**2. MakeGinRequest(t, app, method, path, body, headers) *ResponseRecorder**
- 发送 HTTP 请求到 Gin 路由
- 支持 JSON 请求体和自定义请求头
- 返回响应记录器

**3. ParseResponse(t, w, v)**
- 解析 JSON 响应到指定结构体

**4. AssertStatusCode(t, w, expected)**
- 断言 HTTP 状态码

**5. AssertResponseCode(t, w, expected)**
- 断言业务响应码 (response.code)

**6. CreateTestUser(t, app, studentID, password, role) string**
- 创建测试用户并返回 JWT token

**7. WithAuth(token) map[string]string**
- 生成带 Authorization 头的请求头

## 测试示例

### 1. 用户注册和登录测试

```go
func TestUserRegisterAndLogin(t *testing.T) {
    s, cleanup := testutils.SetupTestServer(t)
    defer cleanup()

    app := s.GetApp()

    t.Run("用户注册成功", func(t *testing.T) {
        registerBody := map[string]interface{}{
            "student_id": "2021001",
            "username":   "test_student",
            "password":   "password123",
            "email":      "test@student.com",
        }

        w := testutils.MakeGinRequest(t, app, "POST", "/api/v1/user/register", registerBody, nil)

        testutils.AssertStatusCode(t, w, http.StatusOK)
        testutils.AssertResponseCode(t, w, 200)
    })
}
```

### 2. 权限控制测试

```go
func TestUserPermissions(t *testing.T) {
    s, cleanup := testutils.SetupTestServer(t)
    defer cleanup()

    app := s.GetApp()

    // 创建普通学生
    studentToken := testutils.CreateTestUser(t, app, "2021006", "password123", "student")

    // 创建管理员
    adminToken := testutils.CreateTestUser(t, app, "admin001", "admin123", "admin")

    t.Run("普通用户获取用户列表失败", func(t *testing.T) {
        headers := testutils.WithAuth(studentToken)
        w := testutils.MakeGinRequest(t, app, "GET", "/api/v1/user?page=1&page_size=10", nil, headers)

        testutils.AssertStatusCode(t, w, http.StatusForbidden)
    })

    t.Run("管理员获取用户列表成功", func(t *testing.T) {
        headers := testutils.WithAuth(adminToken)
        w := testutils.MakeGinRequest(t, app, "GET", "/api/v1/user?page=1&page_size=10", nil, headers)

        testutils.AssertStatusCode(t, w, http.StatusOK)
    })
}
```

### 3. 完整业务流程测试

```go
func TestSubmitProblem(t *testing.T) {
    s, cleanup := testutils.SetupTestServer(t)
    defer cleanup()

    app := s.GetApp()

    // 1. 创建测试用户
    token := testutils.CreateTestUser(t, app, "2021007", "pass123", "student")
    headers := testutils.WithAuth(token)

    // 2. 创建题目（作为管理员）
    adminToken := testutils.CreateTestUser(t, app, "admin002", "admin", "admin")
    problemBody := map[string]interface{}{
        "title": "两数之和",
        "difficulty": "easy",
        "description": "给定一个整数数组...",
    }
    
    w := testutils.MakeGinRequest(t, app, "POST", "/api/v1/problems", problemBody, testutils.WithAuth(adminToken))
    testutils.AssertStatusCode(t, w, http.StatusOK)

    var problemResp struct {
        Data struct {
            ID string `json:"id"`
        } `json:"data"`
    }
    testutils.ParseResponse(t, w, &problemResp)
    problemID := problemResp.Data.ID

    // 3. 提交代码
    submitBody := map[string]interface{}{
        "problem_id": problemID,
        "language": "python",
        "code": "def twoSum(nums, target): ...",
    }

    w = testutils.MakeGinRequest(t, app, "POST", "/api/v1/submits", submitBody, headers)
    testutils.AssertStatusCode(t, w, http.StatusOK)

    // 4. 查询提交结果
    var submitResp struct {
        Data struct {
            ID string `json:"id"`
        } `json:"data"`
    }
    testutils.ParseResponse(t, w, &submitResp)

    w = testutils.MakeGinRequest(t, app, "GET", "/api/v1/submits/"+submitResp.Data.ID, nil, headers)
    testutils.AssertStatusCode(t, w, http.StatusOK)
}
```

## 测试最佳实践

### 1. 独立性
- 每个测试应该独立，不依赖其他测试的执行顺序
- 使用不同的测试数据（如不同的 student_id）
- 使用 `t.Run()` 创建子测试

### 2. 清理
- 使用 `defer cleanup()` 确保资源清理
- 测试结束后清理创建的数据（可选）

### 3. 可读性
- 使用描述性的测试函数名和子测试名
- 测试步骤清晰，有必要的注释

### 4. 覆盖度
- 正常流程（Happy Path）
- 边界条件
- 错误处理
- 权限控制

### 5. 性能
- 避免在测试中执行耗时操作
- 使用 mock 或 stub 替代外部依赖（如沙箱服务）

## 测试配置

### 环境变量
测试使用开发环境配置，确保 `conf/config.yaml` 中的数据库连接正确。

### 数据库隔离
建议使用独立的测试数据库，避免影响开发环境数据：
- 修改 `conf/config.yaml` 中的 `Mongo.Database` 为测试库名
- 或使用环境变量覆盖配置

### Mock 外部服务
对于沙箱服务等外部依赖：
- 可以使用真实服务（集成测试）
- 或创建 mock 实现（单元测试）

## 持续集成

### GitHub Actions 示例
```yaml
name: Run Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      mongodb:
        image: mongo:5
        ports:
          - 27017:27017
      redis:
        image: redis:7
        ports:
          - 6379:6379

    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-go@v4
        with:
          go-version: '1.24'
      
      - name: Run Tests
        run: go test ./... -v -coverprofile=coverage.out

      - name: Upload Coverage
        uses: codecov/codecov-action@v3
        with:
          files: ./coverage.out
```
