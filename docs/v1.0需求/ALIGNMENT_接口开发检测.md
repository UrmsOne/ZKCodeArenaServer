## 2. 项目上下文分析

### 2.1 技术栈
- **后端框架**: Golang 1.23+ / Gin
- **数据库**: MongoDB 4.4+
- **缓存**: Redis
- **判题引擎**: go-judge (沙箱评测系统)
- **认证**: JWT
- **部署**: Docker + Docker Compose
- **其他依赖**:
  - QR Code: skip2/go-qrcode
  - 日志: logrus + lumberjack
  - 加密: golang.org/x/crypto

### 2.3 架构模式
- **分层架构**: Server (Controller) → Service → DB
- **数据库设计**: 
  - Course (课程) - 独立集合
  - Clazz (班级) - 独立集合，关联 course_id
  - Task (任务) - 嵌入在 Clazz 中
  - User, Problem, Submit - 独立集合

## 3. 需求理解与接口分析

### 3.1 模块一: 用户模块/注册登录

#### 3.1.1 需求功能点
1. ✅ 学生注册：填写学号、姓名、手机号、密码，支持通过班级邀请码关联班级
2. ⚠️ 教师注册：填写工号、姓名、手机号、密码，提交后进入管理员审核队列
3. ⚠️ 校外学习者注册：填写姓名、手机号、密码，无需关联班级
4. ❌ 密码找回：支持手机验证码重置，管理员后台可强制重置用户密码
5. ⚠️ 首页 - 角色化登录跳转：超管→用户管理页，教师→课程管理页，学生/学习者→个人学习页
6. ⚠️ 超管首页：包含系统所有用户管理、教师账号审核功能
7. ⚠️ 教师首页：展示教师名下课程和班级信息
8. ⚠️ 学生首页：展示已达成数据、所在班级待完成任务，设置核心功能快捷入口
9. ✅ 用户设置 - 个人设置页：支持查看/编辑基础信息（姓名、手机号、头像），修改登录密码
10. ✅ 会话管理：支持保持登录状态7天，设置token有效期
11. ✅ 角色权限控制：防止越权访问，仅展示当前用户可见模块

### 3.2 模块二: 班级与课程模块

#### 3.2.1 需求功能点 - 课程模块
1. ✅ 课程管理页：教师登录默认进入，展示课程名称、关联班级数、任务数、创建时间

## 5. 疑问澄清

### 5.1 业务逻辑疑问

#### Q1: 班级与课程的关系
**问题**: 需求文档中提到"课程创建时选择关联已创建班级"，但数据模型是班级关联课程ID，这是否矛盾？

**分析**: 
- 数据模型: `Clazz.CourseId` (班级属于课程)
- 需求描述: 课程关联班级
- 实际实现: 创建班级时指定课程ID

**建议**: 需要明确业务逻辑，一个课程可以有多个班级，一个班级属于一个课程。当前实现是正确的，但需要接口支持"查询课程下的所有班级"。

#### Q2: 学生角色类型
**问题**: 需求提到"校外学习者"，但代码中只有 student 角色，是否需要区分？

**选项**:
1. 新增 `learner` 角色
2. 使用 `student` 角色 + `is_external` 字段区分
3. 不区分，都作为 student

#### Q3: 课程的"学期"字段
**问题**: 需求提到填写"学期"，但 Course 模型没有该字段。

**影响**: 需要添加 `semester` 字段用于课程分类。

#### Q4: 任务类型
**问题**: Task 有 `Type` 字段(题单/视频)，但只有题单类型在使用，视频资源如何管理？

**建议**: 需要明确视频资源的数据模型和存储方式。

#### Q5: 教师审核流程
**问题**: 教师注册后进入审核队列，需要什么状态管理？

**建议**: User 模型需要添加:
- `approval_status`: pending/approved/rejected
- `approved_by`: 审核人ID
- `approved_at`: 审核时间

#### Q6: 密码找回
**问题**: 需要集成短信验证码服务，是否有供应商？

**影响**: 需要第三方服务(阿里云、腾讯云等)，涉及配置和成本。
